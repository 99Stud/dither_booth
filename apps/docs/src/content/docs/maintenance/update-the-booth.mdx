<Aside type="caution">
  Update **between events**, on a network with internet, with time to test.
  Never update at a venue an hour before doors open.
</Aside>

## Update the booth software

The booth runs whatever is checked out in `/opt/dither-booth`, built. Updating means pulling `main`, rebuilding, and restarting.

<Steps>

1. **Pull, install and build:**

   ```bash
   sudo booth repo
   ```

   This runs `git pull --ff-only`, `bun install` and `bun run build` (the apps and these docs) as the service user. It refuses to pull over local changes; that's deliberate, the booth's checkout should never be edited by hand.

2. **Restart the apps:**

   ```bash
   sudo systemctl restart ditherbooth.service
   ```

   Database migrations apply on their own when the engine starts. A restart also revokes Darkroom sessions.

3. **Apply system-level changes, if any.** Re-running these is always safe; they change nothing when already up to date:

   ```bash
   sudo booth network setup   # when doctor says "Network setup out of date"
   sudo booth service         # when the systemd unit changed
   ```

4. **Check:**

   ```bash
   booth doctor
   ```

   Then a test print from the Darkroom and one full visit.

</Steps>

## Update the CLI

The CLI is a separate binary, released from Git tags. Re-run the installer to get the latest release:

```bash
curl -fsSL https://github.com/99Stud/dither_booth/releases/latest/download/install.sh | sudo bash
booth --version
```

Update the CLI **before** the software when a release notes says so: a newer `network setup` or `service` may be needed by the new software.

## Update the operating system

```bash
sudo apt update && sudo apt full-upgrade -y
sudo rpi-eeprom-update -a
sudo reboot
```

After the reboot, run `booth doctor`. A Chromium update from apt changes the browser the engine renders receipts with; check a test print.

## Roll back

The checkout is a normal Git repo. To go back to a known good commit:

```bash
cd /opt/dither-booth
sudo -u pi git log --oneline -10
sudo -u pi git checkout <commit>
sudo -u pi bun install && sudo -u pi bun run build
sudo systemctl restart ditherbooth.service
```

Then return to `main` (`git checkout main`) before the next `booth repo`, which only fast-forwards.

<Aside type="danger" title="Migrations don't roll back">
  Migrations are forward-only. Rolling back across a migration leaves a newer
  database under older code. Before an update that ships a migration, [back up
  the database](/docs/maintenance/recovery/#back-up-the-database).
</Aside>
