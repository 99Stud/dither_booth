## At a glance: admin

Admin's **Control Center → Health checks** is the first place to look. It checks, live:

| Item                | Healthy when                                                                                                                                                                                                                                              |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Engine**          | The engine answers.                                                                                                                                                                                                                                       |
| **Shutter**         | The Shutter server answers. The item lists every connected kiosk page and which screen it shows.                                                                                                                                                          |
| **Camera**          | The Experience page on the iPad reports a working camera. A denied or failed camera is unhealthy.                                                                                                                                                         |
| **Printer**         | The printer watch says it can print. Paper low is healthy with a warning.                                                                                                                                                                                 |
| **Ticket renderer** | The headless Chromium (Puppeteer) the engine uses to lay out tickets has its page loaded.                                                                                                                                                                 |
| **Pi**              | The Pi isn't throttling now, is under 80 °C, has over 5 % of memory and of each disk free, and its 1 min load is under twice its cores. Warm (70 °C), a throttle flag since boot, under 15 % free, or load past the cores shows a warning, not a failure. |

Each unhealthy item says why, and offers the recovery that fits: reload the kiosk page, re-initialize Puppeteer, or restart a PM2 process. Each item's **View logs** opens the [Logs page](/docs/maintenance/logs/#open-logs) filtered to that part of the booth. The Pi's **View system** opens the [System page](/docs/maintenance/system/), with the last hour of every reading.

The Darkroom shows a compact version of the same checks in its **Booth status** strip.

## Full check: `booth doctor`

Over SSH, `booth doctor` checks the whole Pi, in this order:

| Check                                 | Fails or warns when                                                                                              | Fix                                                                                               |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| SSD mounted at `/mnt/ssd`             | Not mounted                                                                                                      | `sudo booth ssd`; check `lsblk -f`                                                                |
| Data symlink                          | `apps/engine/data` doesn't point to `/mnt/ssd/dither-booth/data`                                                 | `sudo booth ssd`; if it refuses, [Recovery](/docs/maintenance/recovery/#the-data-symlink-is-gone) |
| Bun installed                         | No Bun at `~pi/.bun/bin/bun`                                                                                     | `sudo booth bun`                                                                                  |
| Cert IP                               | No TLS manifest, or the certificate was issued for another IP (warn)                                             | `booth cert` (or wait for the next service start)                                                 |
| `ditherbooth.service` enabled         | Not enabled                                                                                                      | `sudo booth service`                                                                              |
| PM2 processes                         | A process isn't `online`, or the service isn't running                                                           | See [Logs](/docs/maintenance/logs/), then `sudo systemctl restart ditherbooth`                    |
| PM2 logs rotated                      | No `/etc/logrotate.d/ditherbooth`, or it's older than the software (warn), or logrotate isn't hourly (warn)      | `sudo booth service`                                                                              |
| `pi` can read the system journal      | `pi` isn't in `systemd-journal` (warn)                                                                           | `sudo booth service`                                                                              |
| Runs a release; admin can update it   | The update or rollback unit is missing or older than the software, or the booth still runs a git checkout (warn) | `sudo booth service`; on a checkout, `sudo booth update`                                          |
| Admin can restart, reboot, power off  | With `sudo` only: the Power panel's polkit rule is missing or older than the software (warn)                     | `sudo booth service`                                                                              |
| engine, shutter, admin `healthz`      | Unreachable or invalid payload                                                                                   | Same as above                                                                                     |
| Setup page                            | `http://<ip>:3003/healthz` unreachable                                                                           | It's served by the Shutter: restart the service                                                   |
| `ditherbooth-network.service` running | Not running (warn: no booth Wi-Fi fallback)                                                                      | `sudo booth network setup`                                                                        |
| Network setup up to date              | The booth Wi-Fi's captive DNS or Wi-Fi permissions are older than the software (warn)                            | `sudo booth network setup`                                                                        |
| Reachable as `<hostname>.local`       | avahi not answering, or the booth was renamed (warn)                                                             | `sudo systemctl restart avahi-daemon`                                                             |

`doctor` exits with code `1` if any check **fails**; warnings don't fail it. Run it with `sudo` to include the root-only checks (the polkit rules).

<Aside type="tip">
  Run `booth doctor` after every update and before every event. It's fast and
  catches most problems before guests do.
</Aside>

## Raw endpoints

Each process serves a `healthz` endpoint returning JSON:

```bash
curl http://127.0.0.1:3001/healthz          # engine, loopback only
curl -k https://<booth-ip>:3000/healthz     # shutter
curl -k https://<booth-ip>:3002/healthz     # admin
curl http://<booth-ip>:3003/healthz         # setup page
```

`-k` skips certificate verification for a quick check from a machine that doesn't trust the booth CA.

## System health

Admin's [System page](/docs/maintenance/system/) shows all of this live, with the last hour, and keeps working while the engine is down. Over SSH, the same readings:

```bash
vcgencmd get_throttled   # 0x0 = never throttled or under-volted
vcgencmd measure_temp
free -h                  # memory, including zram swap
df -h / /mnt/ssd         # SD card and SSD space
```

A non-zero `get_throttled` means under-voltage (use the official 27 W supply) or overheating (check the cooler and that the M.2 shield doesn't block the blower).
