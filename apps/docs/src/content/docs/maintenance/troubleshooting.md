Start with admin's **Control Center → Health checks** and, over SSH, `booth doctor`. Most problems show up there with the fix. To see why, open a health item's **View logs**, or admin's [Logs page](/docs/maintenance/logs/#open-logs). If not, find the symptom below.

## Getting in

| Symptom                                                               | Check                                                                                                                                                                                                                    |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| No ticket at power-on                                                 | Printer powered, paper loaded, cover closed. The ticket waits until the printer can print. Then the USB cable. Over SSH: `booth qr` shows the same QR.                                                                   |
| Can't SSH to `booth.local`                                            | Same network as the booth? Try the IP from the ticket. On the booth Wi-Fi: `ssh pi@10.42.0.1`.                                                                                                                           |
| Setup QR: “Safari can't open the page… not connected to the internet” | The iPad has no IPv4 route to the booth (Wi-Fi address `192.0.0.2`, as on an iPhone hotspot). Scan the ticket's second QR (`http://<hostname>.local:3003`), or run on the booth Wi-Fi.                                   |
| Setup page times out on the venue Wi-Fi                               | The venue isolates devices. [Run on the booth Wi-Fi](/docs/venue/wifi/#run-the-event-on-the-booth-wi-fi).                                                                                                                |
| `<hostname>.local` doesn't open, the IP does                          | avahi renamed the booth (`booth-2.local`). `booth network watch` takes the name back within a minute; `sudo systemctl restart avahi-daemon` does it at once. If it comes back renamed, another device has the same name. |
| Safari: certificate warning, or no camera                             | The iPad doesn't trust the booth CA. [Connect a device](/docs/venue/connect-a-device/). If it trusted it before, the booth may have a **new CA** (reflash, new mkcert): trust again.                                     |
| Certificate for the wrong IP                                          | It's re-issued at service start. `booth cert --if-changed`, then `sudo systemctl restart ditherbooth`; `booth doctor` confirms.                                                                                          |

## Wi-Fi

| Symptom                                                     | Check                                                                                                                                                       |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The Wi-Fi picker doesn't open on the booth Wi-Fi            | Scan the Wi-Fi ticket's second QR and use Darkroom → Wi-Fi. If it never appears: `booth doctor` → “Network setup out of date” → `sudo booth network setup`. |
| Booth Wi-Fi takes a minute to come back after a failed join | Same: `sudo booth network setup`.                                                                                                                           |
| Booth joined a network the iPad can't reach                 | Power off and on twice within two minutes: the booth Wi-Fi opens.                                                                                           |
| No booth Wi-Fi ever opens                                   | `systemctl status ditherbooth-network.service`. Not running → `sudo booth network setup`. No Wi-Fi adapter found → check `nmcli device`.                    |
| Join fails with “Wrong password”                            | Retype it on the captive page. Passwords are at least 8 characters; an empty password is for open networks only.                                            |
| Venue Wi-Fi has a login page                                | Not supported. Run on the booth Wi-Fi.                                                                                                                      |

## Printer

| Symptom                                   | Check                                                                                                                                                                  |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admin shows **Not connected**             | USB cable, printer power. `lsusb \| grep -i 04b8` should list it. The engine reconnects on its own within seconds of the printer reappearing.                          |
| Printing fails with `LIBUSB_ERROR_ACCESS` | The service user can't open the USB device. `sudo usermod -aG lp pi`, then reboot.                                                                                     |
| Booth in maintenance, printer looks fine  | Admin's Printer card says which condition holds. Cover fully latched? Paper past the sensor? If a sensor misbehaves, turn **Automatic** off for the event and note it. |
| Admin shows **Checking** for a long time  | The printer is connected but never sent a status. Power-cycle the printer.                                                                                             |
| Prints faint or washed out                | Raise the printer's print density; some rolls are thick. Then [tune the prints](/docs/venue/tune-prints/).                                                             |
| Vertical white lines                      | Clean the print head.                                                                                                                                                  |
| Half a receipt after a paper-out          | Expected: the job is aborted. The next job clears the printer's buffer first.                                                                                          |
| Prints from another program don't work    | The engine holds the printer exclusively while it runs. Stop the service first.                                                                                        |

## Booth screen (iPad)

| Symptom                                        | Check                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Background broken, screen frozen, layout wrong | Admin → Health → Shutter → **Reload** (when idle, or now). A tab whose JavaScript is fully frozen needs a manual reload on the iPad.                                                                                                                                                                                                                                                                                                                              |
| “Be right back” and you didn't switch it on    | The printer can't print (see Printer). Admin's Booth screen card lists the reasons.                                                                                                                                                                                                                                                                                                                                                                               |
| Camera item unhealthy in admin                 | Its message says which. “Camera permission denied.”: Safari's camera permission for the Shutter. “The camera is in use by another app.”: close that app. “The camera gives no picture.” or “The camera stopped.”: the page reopens the camera by itself, three times. If the message ends “Close the browser fully and open the Shutter again.”, the browser's camera has hung: swipe Safari away on the iPad and open the Shutter again. A reload is not enough. |
| **Start** does nothing on the landing screen   | The camera isn't showing a picture yet, or is reopening. Admin → Health: check the **Camera** item and follow the row above.                                                                                                                                                                                                                                                                                                                                      |
| Visit stuck on “printing…”                     | It gives up after 45 s and resets. Check the printer and the ticket renderer in Health.                                                                                                                                                                                                                                                                                                                                                                           |
| Darkroom says “Too many wrong PINs”            | Wait a minute.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Darkroom locked itself                         | 30 minutes without use, a PIN change, or an engine restart. Enter the PIN again.                                                                                                                                                                                                                                                                                                                                                                                  |

## Receipts and the engine

| Symptom                                                           | Check                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ticket renderer (Puppeteer) unhealthy                             | Admin → Health → **Re-initialize Puppeteer**. Persistent: `sudo booth install` re-installs Chromium's libraries, then `booth doctor`.                                                                                                   |
| A PM2 process keeps restarting                                    | Admin's **Logs** page: “restarted” dividers, and the **Error** lines just before each. Over SSH: `bun run pm2:list` for the restart count, then the `"type":"err"` lines of its `<process>.log`. See [Logs](/docs/maintenance/logs/).   |
| `EADDRINUSE` at start                                             | An old process still holds the port. `sudo systemctl restart ditherbooth`; if it persists, find it with `sudo ss -ltnp \| grep 300`.                                                                                                    |
| Lottery never wins                                                | Lottery is off, prizes are out of stock (the Hub warns **Lottery empty** when every one is), or a pause after a win is running. Check the Event page's odds card.                                                                       |
| Wrong look on screen or tickets                                   | The event's kit. A kit the release doesn't ship falls back to the default (`event-kit-unknown` in the logs).                                                                                                                            |
| Tickets read the wrong way up                                     | Admin → Settings → Printing: pick the other end (**Bottom first** or **Top first**), then **Print a sample ticket** to check.                                                                                                           |
| A partner logo is missing from a ticket                           | The ticket printed without an image that wouldn't load (`receipt-image-failed` in the logs names it). Admin → Event → Kit → **Partners**, take it out of the row, remove it from the **Logo library**, upload it again and add it back. |
| The photo is missing from a kit's ticket, the logo over it prints | The kit's mask over the photo didn't load, and a mask that fails hides the photo (`receipt-image-failed` names `/photo-mask-…`). Releases up to 0.7.0 shipped the mask at the wrong path: update the booth.                             |
| No partner row on the photo receipt                               | The event has no partner logos. Admin → Event → Kit → **Partners** → **Add logo**.                                                                                                                                                      |

## The Pi itself

| Symptom                                                       | Check                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `nvme0n1` missing from `lsblk`                                | Ribbon cable orientation and latches, `dtparam=pciex1` in `/boot/firmware/config.txt`, bootloader updated with `rpi-eeprom-update -a`.                                                                                                                                                                                                                                                                                                                                                                        |
| `booth ssd` can't find the SSD partition                      | It needs an unmounted ext4 partition. Force one with `BOOTH_SSD_DEVICE=/dev/nvme0n1p1`.                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `booth ssd`: “Both … hold dither-booth.sqlite”                | The data symlink is gone and the engine made a second database on the SD card. Nothing was moved. Follow [The data symlink is gone](/docs/maintenance/recovery/#the-data-symlink-is-gone).                                                                                                                                                                                                                                                                                                                    |
| Throttling, loud fan                                          | Admin's [System page](/docs/maintenance/system/): **Temperature** and **Throttling** say which flag is set, now or since boot. Over SSH, `vcgencmd get_throttled` (`0x0` is fine). Official 27 W supply? Cooler contact, blower intake clear?                                                                                                                                                                                                                                                                 |
| System page: **Under-voltage** since boot                     | The supply dipped at least once since the Pi started. Use the official 27 W supply, and check the USB-C cable. The flag clears on the next restart.                                                                                                                                                                                                                                                                                                                                                           |
| Software panel: **Couldn't check for updates**                | The booth has no internet (on the booth Wi-Fi, or a venue network that blocks it). Updates need internet; the booth runs fine without.                                                                                                                                                                                                                                                                                                                                                                        |
| Software panel: **The booth didn't start it**                 | The unit started but wrote no job. Read the update's lines on the Logs page, under **System** (`journalctl -t booth` over SSH).                                                                                                                                                                                                                                                                                                                                                                               |
| `booth update`: **Nothing changed, the booth still runs …**   | The update stopped before the switch; the reason follows. No internet, no such release (`sudo booth update 0.8.0`: is the tag pushed and its release published?), not 1 GB free, or a download that doesn't match `SHA256SUMS` (run it again).                                                                                                                                                                                                                                                                |
| `booth update`: **Rolled back to …**                          | The new release didn't come up within 2 minutes. The reason follows; the full run is in `journalctl -u 'ditherbooth-update@*'`, and the apps' in the [Logs page](/docs/maintenance/logs/). The booth runs the release before, with its database.                                                                                                                                                                                                                                                              |
| `booth rollback` refuses: the database changed                | The newer release applied migrations. `sudo booth rollback --restore-db` restores the backup taken before that update; visits since are lost.                                                                                                                                                                                                                                                                                                                                                                 |
| `booth repo`: **runs a release, not a checkout**              | Expected once a booth runs releases. Update with `sudo booth update`.                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Power or Software panel: **The booth doesn't allow this yet** | The booth's system polkit rule is missing, out of date, or one polkit can't load: the rule written by the 0.8.0 CLI and its release candidates isn't, and `journalctl -u polkit` says **Error compiling script … 50-ditherbooth-system.rules**. Run `sudo booth update` over SSH: it installs the release's CLI, which writes the rule again. A booth that predates `booth update` needs `sudo booth service` instead. `sudo booth doctor` then passes **Admin can restart, reboot and power off the booth**. |
| Power panel: **Not answering** after 5 minutes                | The booth didn't come back after a restart or reboot. Is it plugged in, and is your device on its network? A reboot that joined another network moves the booth's address: see [Wi-Fi](#wi-fi).                                                                                                                                                                                                                                                                                                               |
| System page says **Not on a Pi**                              | Expected off the Pi (a development machine): heat, fan and throttling only exist on the booth. On the booth, **Throttling** alone saying so means `vcgencmd` failed: is `pi` in the `video` group?                                                                                                                                                                                                                                                                                                            |
| `Error opening terminal: xterm-ghostty`                       | The Pi has no terminfo for Ghostty. Prefix commands with `TERM=xterm-256color`, or copy the entry: `infocmp -x xterm-ghostty > xterm-ghostty.ti` on the Mac, then `tic -x xterm-ghostty.ti` (and `sudo tic -x`) on the Pi.                                                                                                                                                                                                                                                                                    |
| SD card or SSD full                                           | `df -h / /mnt/ssd`. PM2 logs in `/opt/dither-booth/logs/pm2/` are rotated daily, or past 20 MB checked hourly: `booth doctor` says if the rule is missing (`sudo booth service`). Rotate now with `sudo logrotate --force /etc/logrotate.d/ditherbooth`, and delete old `-out.log` and `-err.log` files.                                                                                                                                                                                                      |
